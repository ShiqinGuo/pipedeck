# 视觉、交互与验收

Status: Current
Owner: TripGuru Product Design + TripGuru Engineering

## 视觉方向

界面采用“本地开发控制台”语言：深色中性工作区、橙色主动作、绿色健康状态、蓝色信息状态。信息密度服务于长时间扫描与重复操作，不使用营销 Hero、装饰性渐变、嵌套卡片或大面积品牌色背景。

- 正文字体使用 IBM Plex Sans，代码、端口和分支使用 IBM Plex Mono。
- 8px spacing grid；控件圆角不超过 6px；项目目录使用 64px 稳定行高，桌面主要操作使用 38–40px 高度，移动触控目标不低于 44px。
- 图标来自 Lucide；图标按钮必须有可访问名称和 tooltip。
- 框架与中间件识别素材固定迁移自 Simple Icons 16.28.0，并随客户端离线打包；来源和商标声明由仓库根目录 `THIRD_PARTY_NOTICES.md` 负责。
- 状态不得只依赖颜色，同时使用图标和文本。
- 页面层级为 60px 应用图标轨、项目目录、工作区标题与动作、服务/依赖上下文。
- 页面标题、区块标题、主信息和辅助信息分别使用 18px、14px、13px 和 11–12px；10px 只用于短 badge 与全大写 eyebrow，不使用 8–9px 正文。

## 开源 GUI 参考

2026-08-14 重做时只借鉴公开交互模式，不复制产品代码、品牌素材或逐像素视觉。

- [Podman Desktop](https://podman-desktop.io/docs/discover-podman-desktop)：采用资源导航、紧凑列表和从资源进入 Summary/Logs/Terminal 的上下文切换。
- [DevPod](https://devpod.sh/docs/developing-in-workspaces/create-a-workspace)：采用 Workspace-first 模型，以及从 Git 仓库或本地目录创建工作区的入口语义。
- [Dockge](https://github.com/louislam/dockge)：采用 Stack-first 详情页，将服务、Compose 配置、执行动作和实时输出保持在同一个上下文。
- [GitButler](https://github.com/gitbutlerapp/gitbutler)：只借鉴桌面端的高密度主对象布局、顶栏动作和持续可见的 Git 状态；不使用其代码和素材。

TripGuru Local 的组合结果是：左侧项目目录负责发现和选择；中央工作区服务负责说明将运行什么；右侧运行依赖负责数据库与中间件绑定；生成计划始终位于工作区标题栏。

## 交互设计

- 总览：确认 Docker、API、仓库和中间件是否可用。
- 项目目录：搜索、按类型过滤、多选项目，dirty 项目持续可见。
- 工作区配置：选择运行模式和中间件目标，所有默认值可见。
- 仓库接入：目录页提供“导入本地仓库”和“克隆仓库”两个明确入口；克隆表单展示目标目录、分支和认证边界，不接收 Token 或密码。
- 工作区配置：服务详情使用页内 inspector 编辑 argv token、Host/Compose target、endpoint、readiness、普通变量、ConnectionProfile 和 Secret 引用；不把复杂配置塞进项目列表行。
- 运行预检：按顺序展示类型化命令、阻断项和恢复动作；只有当前配置预检通过后才显示“开始运行”。
- 运行工作台：阶段导航、服务状态和日志保持同一上下文；日志支持 stdout/stderr 过滤、自动跟随和复制，但不提供编辑入口。
- 历史：按状态、工作区和时间扫描 Run；失败记录直接展示失败命令、恢复动作和“重新预检后重试”。
- 部署：按 target 扫描 revision、不可变 image、previous 与恢复状态；degraded 直接提供受 token 保护的 reconcile 动作。
- 进程：资源页把宿主进程与 Docker 中间件分成两个明确视图，进程行可跳转所属 Run 并执行取消。
- 清理：资源页先进入选择和预览，再确认执行；不可删除原因常驻，MinIO 从不出现可选框。
- 错误恢复：目录失败可重试；单个项目解析失败不阻断其他项目；表单错误就地显示。
- 危险操作：必须先预览受影响资源，且外部资源永不出现可执行删除入口。

## 视觉验收

- 1440x900 首屏能看到导航、工作区标题、项目列表和配置区，不发生遮挡或横向溢出。
- 1024x768 保留核心列表和主要动作，辅助信息可折叠。
- 390x844 按“目录、工作区服务、运行依赖、计划”顺序单列重排；按钮和最长项目名不溢出。
- 正文、控件和状态满足 WCAG AA 对比度；键盘焦点轮廓始终可见。
- loading 不改变主要布局尺寸；empty、error、success 的视觉层级一致。

## 交互验收

- 选择项目后，已选数量、配置区和计划请求保持一致。
- 搜索无结果时显示清空筛选动作。
- API 断开时不回退到 mock 数据，重试成功后恢复真实列表。
- 中间件选择变化会使旧计划失效，并明确要求重新生成。
- 只有 `healthy` 或 `running` 的实例可自动绑定；没有健康候选时按中间件种类显示阻断和恢复动作。
- dirty 项目显示警告但允许生成计划；未来执行更新时必须阻断覆盖。
- 所有请求中的 loading 会禁用重复提交，失败后允许安全重试。
- 保存工作区、预检和运行是三个不同动作，按钮文案和状态不能互相冒充。
- Secret 管理允许创建、更新和删除 Credential Manager value，但 value 不回显；工作区只选择 metadata 引用，并明确 missing/in-use 恢复。
- Run 处于 `running` 时主动作是取消；终态时才显示重试，重试必须创建新记录。
- 日志轮询失败不把 Run 伪装成失败，恢复连接后从最后事件序号继续。
- 清理确认展示准确资源名、类型和跳过原因；执行返回部分成功时逐项呈现。
- 移动端首次选择项目后将项目目录收起为 64px 摘要，用户可以显式展开；已配置首屏必须看到服务和第一个运行依赖。
- 计划对话框初始焦点、Escape 关闭、Tab 焦点约束和关闭后焦点返回都必须可验证。
