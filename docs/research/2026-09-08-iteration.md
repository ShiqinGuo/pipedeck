# 0.3.0：重复集成测试与桌面交付

日期：2026-09-08。范围延续“本地多项目 CI/CD”：开发者能够确认实际运行的代码、打开业务页面，修改后再次集成测试。

## 复查方法与外部依据

从配置编辑、分支选择、预检启动、观察、业务测试、失败恢复和客户端更新逐步核查，分别审计运行生命周期、前端交互和桌面交付；对发现的问题构造真实进程、SQLite 并发、浏览器或打包产物证据。

- [Docker Compose 启停顺序](https://docs.docker.com/compose/how-tos/startup-order/)强调启动与就绪的区别，也说明了依赖顺序和依赖重启。本轮重点检查混合 Host/Compose 失败后是否留下无法管理的进程。
- [Compose Watch](https://docs.docker.com/compose/how-tos/file-watch/)提供同步、重启与重建等更新动作。对 Pipedeck 的启示是衡量修改后再次可测的成本；在进一步自动更新之前，先保证单次执行和旧实例的状态可靠。
- [Tilt 自定义按钮](https://docs.tilt.dev/buttons.html)将日常命令及日志关联到资源。测试数据准备和业务冒烟值得后续做成明确动作，本轮先补齐进入应用和找到对应运行的链路。

以上用于选择交互和执行模式，不作为市场需求或线上环境等价性的证明。

## 本轮已实现

| 问题及影响 | 本轮处理 | 验证 |
| --- | --- | --- |
| Host 已启动，下游 Compose 失败/取消后进程遗失，继续占端口 | 终态统一回收本次拥有的进程；取消与启动同步 | 真实子进程失败、异常、取消及解析期间取消 |
| 双击或两个调用者可启动同一工作区两次 | SQLite 同事务限制一个 queued/running，原幂等键仍复用；409 返回现有 Run ID | 两个数据库连接并发提交、真实 API 重复请求 |
| 应用分支后旧进程从当前配置中消失 | 活跃运行阻断分支应用/删除；运行面板保留已移除的 Host/Compose 目标和恢复入口 | Environment 回归及逐服务 runtime 回归 |
| 新增但未执行的服务误显示为启动中 | 按活跃计划里的项目身份判断 | 独立 runtime 用例 |
| 只能打开根页面，不能直接进 /app、/docs | Host/Compose 优先使用 application.endpoint/path；未配置时兼容 HTTP 就绪端口的根页面；按实际运行的计划快照检查应用入口，编码中文和空格 | 两仓库真实 API→SQLite、入口契约及真实桌面业务测试 |
| Tauri 拦截链接后缺少打开权限 | 桌面使用受限 loopback URL 命令打开系统浏览器，失败可重试 | Rust URL 单测、模拟 IPC 恢复、实际桌面包验收 |
| 保存途中继续输入被响应覆盖 | 保存响应仅替换已提交草稿，后续输入保留并使用新 revision | 延迟保存响应和第二次保存 |
| 删除项目留下不可见依赖，重试还停在旧 Run | 同步清理依赖引用；重试导航新 Run | 浏览器操作契约 |
| 日志持续从头加载，结束后仍轮询 | 按 Run 缓存游标、增量分页、终态补读尾日志后停止 | 游标、尾日志、切换 Run 旧请求隔离 |
| 同名分支难分清项目及是否已应用 | 显示所属源项目与“当前已应用”标记，区分配置与运行 | 桌面/窄屏验收 |
| 打包脚本编码导致新源码未复制，安装包可能携带旧模块 | 脚本使用 ASCII、显式复制循环和 SHA 校验；同时构建 sidecar/CLI，失败即停止 | sidecar/CLI 各 34 个模块与当前源码匹配 |
| 更新脚本按全局进程名终止程序并清空目录 | 安装按路径归属原位升级并校验版本 | 本机 0.1.0 → 0.3.0；原有 9 张状态表全部行保持一致 |

## 验收记录

本轮源码验证：后端全量 243 项通过，随后新增的 runtime 专项 5 项通过，合计覆盖当前 248 个用例。前端单元 8 项、浏览器 78 个执行用例通过（22 个既有重复窄屏场景显式跳过）；Rust 2 项通过。浏览器最初两项桌面入口测试缺少 Tauri 环境标记，修正测试夹具后专项 4 项全部通过。

Ruff 格式/检查、Pyright、ESLint、TypeScript、Web build、Cargo 格式/测试、OpenAPI 类型同步和 PowerShell 语法验证通过。既有 Fast Refresh、依赖弃用与 bundle 大小提示不影响上述结果。新增 GitHub Windows CI 覆盖 Host 集成和浏览器验收；需要 Linux Docker daemon 的用例在本机发布验收执行。

实际打包桌面验收使用 0.3.0 客户端和隔离 SQLite 状态库，未 mock 后端或 Tauri。通过桌面预检启动两个真实 Git 仓库中的依赖服务，面板显示 2 / 2 服务就绪；“打开应用”启动真实系统 Edge。随后在浏览器表单中填写并保存中文记录，页面显示成功，直接查询业务 SQLite 确认存储内容一致。通过 API 取消运行后，两服务均变为 stopped，应用 URL 撤下。

桌面 WebView 的 Playwright CDP 坐标点击在本机不可靠，因此桌面按钮通过 DOM click 调用真实事件处理器；系统浏览器中的业务表单由 CUA 实际操作。该验收证明真实桌面、系统浏览器、服务和数据库的联通与停止恢复，没有把坐标点击能力或任意业务功能覆盖率算作已验证。

打包问题定位为 Windows PowerShell 5.1 按 CP936 读取无 BOM 的 UTF-8 脚本，导致含中文的注释吞掉后续复制行。修复为 ASCII 脚本、显式源码复制循环和逐文件 SHA 校验后，sidecar 与 CLI 产物各 34 个模块均与当前源码匹配。

本机已从 0.1.0 原位升级至 0.3.0（`D:\apps\Pipedeck`），控制服务与随包 CLI 均报告 0.3.0。升级前备份本地 SQLite，升级后 9 张状态表的全部行数量与内容哈希一致，包含 6 个仓库、3 个工作区、10 次运行和 3 个分支检出。验收工作区使用独立数据库，没有写入用户状态库。

已安装 sidecar 与 CLI 的全文件 SHA256 与验收产物一致。桌面 EXE 仅有 Tauri 的安装类型常量从 `UNK` 变为 `NSS`（3 字节）；归一化这个官方 bundle 标记后，全文件 SHA256 一致，代码和前端资源一致。NSIS 安装验收通过；MSI 已构建，没有执行第二次安装。公开安装包和对应源码以 [v0.3.0 Release](https://github.com/ShiqinGuo/pipedeck/releases/tag/v0.3.0) 为交付记录。

## 后续值得继续做的事项

1. **项目间地址引用**：选择“后端的 http 入口”来生成前端或 worker 连接配置，统一处理 Host 与容器访问地址，减少手填端口。
2. **测试动作**：把迁移、种子数据、创建测试账号和业务冒烟做成独立、可重复执行的动作，并保留输出与失败恢复。
3. **按项目更新**：保持未变化服务运行，更新指定项目及必要下游；需要先明确源码、镜像和运行版本的对应关系。
4. **整套环境复制与数据隔离**：复制项目组合时一并分配端口、数据库与对象存储范围，不能把新 worktree 当作完整隔离环境。

这些事项暂未实现。本轮没有引入文件监听热更新，也没有为任意实际业务仓库验证完整业务覆盖率。删除 checkout 与同时新建 standalone pipeline 的极端并发仍存在检查/执行间隙，后续应结合统一的仓库操作锁处理。
