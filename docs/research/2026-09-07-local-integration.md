# 本地多项目 CI/CD：研究、评估与优化

日期：2026-09-07。定位由用户明确：本机集成多个项目后，直接测试真实业务功能。

## 外部依据

本次使用官方文档，未开展用户访谈或市场规模调查。此前以 GitHub 星数和 GUI 的存在推导“需求已经验证”的结论不作为本次决策依据。

- [Compose application model](https://docs.docker.com/compose/intro/compose-application-model/)：服务、网络、数据卷和实例分组构成可运行应用。Pipedeck 的增值需要落实到跨仓库配置与执行结果。
- [Tilt 多仓库组织](https://docs.tilt.dev/multiple_repos.html)：允许跨目录组合服务，分别选择需要修改和只需运行的项目。可借鉴明确的项目组合，避免把多项目环境等同于单个 Git ref。
- [Tilt 资源依赖](https://docs.tilt.dev/resource_dependencies.html)：显式依赖控制启动，前置资源就绪后才启动下游。本次增加工作区服务依赖及预检阻断。
- [Compose 启动顺序](https://docs.docker.com/compose/how-tos/startup-order/)：容器启动与服务就绪需要区分。界面分别展示执行记录和当前环境检查结果。

这些资料支持交互与执行模式的选择，不证明采用率或本地环境与线上环境完全等价。

## 已确认并处理的问题

| 问题 | 用户影响 | 改进 |
| --- | --- | --- |
| 分支卡片预检原工作区，没有使用卡片上的 checkout | 可能测试错误代码版本 | 明确选择项目，应用 checkout 后按新 revision 预检 |
| 相同 ref 没有区分项目 | 前后端都用 main/dev 时身份冲突 | 路径与 Environment ID 纳入源项目身份 |
| 服务启动缺少显式依赖 | 前置服务未就绪时下游启动失败 | 缺失/循环依赖阻断，Host 与 Compose 按依赖排序 |
| 运行详情只显示一条部署记录 | 其他服务失败被掩盖，Host 服务不可见 | 逐服务实时检查，全部通过后才计为整体就绪 |
| 运行结果缺少直接测试入口 | 用户还需查找端口和地址 | HTTP 检查通过后提供应用入口和运行记录 |
| 查询刷新重建编辑草稿 | 未保存配置丢失或版本冲突被覆盖 | 保留草稿，新版本冲突时提供明确的重新载入动作 |
| 首页与文档以单 job 首跑为价值中心 | 多项目集成流程不突出 | 改为本地集成、部署和功能测试主线 |

## 验证方法

`tests/test_integration_environment.py` 使用两个独立临时 Git 仓库和控制 API。将前端放在列表首位并显式依赖后端，验证实际构建、启动次序和 readiness。通过前端请求写入后端 SQLite，并从接口和数据库分别读回。保存新配置后，当前服务仍显示原运行版本；取消后撤掉可用入口。

浏览器以模拟 API 验证页面状态与操作契约，覆盖 1440px 和 390px；真实服务测试验证执行行为，两类证据互补。另外通过真实浏览器访问控制台生成的前端入口，输入并保存中文记录，刷新后读回，验证前端、后端和 SQLite 的实际协作。仅健康检查成功而根路径返回 404 的 API 不提供应用链接。命令与结果以本次交付记录为准。

## 后续优先评估

1. 项目间地址的类型化引用，减少手填前后端和 worker 连接地址；支持显式指定应用子路径和 API 文档入口。
2. 数据准备流程：已有迁移、种子数据和冒烟命令如何显式接入。
3. 按项目更新及整套环境复制，同时确定端口、数据库、对象存储的隔离规则。
4. 用实际业务仓库测量首次准备和修改后恢复可测的耗时，决定模板与缓存优先级。

## 本次验证结果

- 后端全量：`uv run pytest -q`，223 passed。随后增加 Docker 只读观测边界用例，`tests/test_deployment_control.py` 与真实双服务集成用例合计 12 passed。
- 浏览器：Playwright 桌面与窄屏 62 passed、22 skipped；跳过项为测试文件显式跳过的重复窄屏写操作，并非失败后跳过。
- 前端单元测试：8 passed；ESLint 无错误，保留 2 个既有 React Fast Refresh 提示；TypeScript 与 Vite build 通过。
- Python 格式、Ruff、Pyright 及 Git diff 空白检查通过。OpenAPI 和前端类型已同步；导出脚本使用临时数据库，避免读取用户运行状态。
- 真实浏览器完成中文记录保存和刷新读回；自动验收还直接查询 SQLite 验证持久化。

本次验证覆盖源码 Web 界面、控制 API、真实 Host 服务和现有 Docker 集成测试；未构建或安装新的 Tauri 桌面发行包。现有依赖弃用和前端包体积提示未影响上述检查结果。
